# ADR-0001. Способ доставки кода на сервер

**Статус:** принято
**Дата:** 2026-10-28

## Контекст

TimeCapsule работает на одном экземпляре EC2 (nginx, PHP-FPM, PostgreSQL). Код нужно регулярно обновлять, при этом важно знать, какая версия работает на сервере, не забывать файлы, а при ошибке уметь быстро вернуть предыдущую версию. Автоматических систем CI/CD у нас пока нет, и инструменты ограничены git и SSH.

## Решение

Единственный источник кода — репозиторий GitHub. Сервер сам забирает код по HTTPS, а выпуск версии выполняется скриптом `deploy.sh` (`git pull --ff-only`, `composer install`, `php bin/init-db.php`, `systemctl reload php-fpm`), который запускается одной командой с компьютера: `ssh ... ./deploy.sh`. Откат делается через репозиторий: `git revert`, `git push` и повторный деплой.

## Рассмотренные альтернативы

1. **Копирование через scp.** Просто для нескольких файлов, но код живёт на ноутбуке, а не в общем месте. Легко забыть файл, непонятно, какая версия на сервере, нет истории и нормального отката. Отказались.
2. **`git pull` вручную на сервере.** Версия известна и есть история, но каждый раз нужно вручную повторять 4–5 команд, и легко пропустить `composer install` или создание таблиц. Результат зависит от внимательности человека. Хорошо как первый шаг, но ненадёжно для регулярных выпусков.
3. **Скрипт `deploy.sh`.** Те же шаги, записанные один раз. `set -euo pipefail` останавливает скрипт при первой ошибке, а `--ff-only` защищает от смешивания ручных правок на сервере с новым кодом. Выбрали этот способ.

## Последствия

**Плюсы:**
- воспроизводимый процесс, одинаковый при каждом выпуске;
- в выводе скрипта видна текущая версия (последний коммит);
- откат прозрачен: история в git не переписывается;
- сервер имеет доступ только на чтение, и его взлом не даёт изменить код в репозитории.

**Минусы и риски:**
- деплой по-прежнему запускается вручную;
- нет тестов и проверок перед выкладкой, и сломанный коммит попадёт на сервер (мы это увидели при проверке с ошибкой 500);
- `git pull` заменяет файлы по одному, поэтому на секунды возможна несогласованная версия;
- `/health` не проверяет реальные страницы;
- пока всё живёт на одном сервере, это единая точка отказа.

В дальнейшем эти шаги можно перенести в CI/CD с автоматическими проверками и откатом.
